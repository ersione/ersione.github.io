Java 21 주요 기능 정리 — 실무에서 바로 쓸 수 있는 것들

#java#java21#virtual-threads#tips

Java 21은 LTS 버전으로, 실무에서 Java 8/11을 쓰고 있다면 마이그레이션을 강력히 권장합니다.

1. Virtual Threads (Project Loom) — 가장 중요한 변화

기존 Java Thread는 OS 스레드와 1:1 매핑입니다. 스레드 1개당 메모리 ~1MB, 최대 수천 개가 한계입니다.

Virtual Thread는 JVM이 관리하는 경량 스레드입니다. 수백만 개도 거뜬합니다.

기존 방식

// 기존: Thread Pool 필수
ExecutorService executor = Executors.newFixedThreadPool(200);
 
// 동시 요청이 200개를 넘으면 대기 큐에서 기다림
executor.submit(() -> {
    // DB I/O, HTTP 호출 등 블로킹 작업
    String result = externalApiCall(); // 🔴 블로킹!
    return result;
});

Virtual Thread

// Virtual Thread: 블로킹 해도 OK!
// I/O 대기 중엔 JVM이 다른 가상 스레드 실행
try (var executor = Executors.newVirtualThreadPerTaskExecutor()) {
    executor.submit(() -> {
        String result = externalApiCall(); // ✅ 블로킹이어도 확장 가능
        return result;
    });
}
 
// Spring Boot 3.2+에서는 설정 한 줄로 활성화
// application.yml:
// spring.threads.virtual.enabled: true

성능 비교

시나리오: 1000개 동시 HTTP 요청, 각 200ms 대기

OS Thread Pool (200):  ~1.5s 완료, CPU 45%
Virtual Thread (1000): ~220ms 완료, CPU 18%

→ 7배 빠르고, CPU는 절반 이하

Virtual Thread 주의사항: synchronized 블록 안에서 블로킹 작업을 하면 Virtual Thread의 장점이 사라집니다 (Pinning). DB 커넥션 풀 라이브러리가 Virtual Thread를 지원하는지 확인하세요. (HikariCP 5.x, R2DBC는 지원)

2. Record Patterns + Pattern Matching

Java 16에서 instanceof Pattern Matching이 나왔고, Java 21에서 Record까지 확장됐습니다.

// Java 21 이전
if (obj instanceof Point) {
    Point p = (Point) obj;
    System.out.println(p.x() + ", " + p.y());
}
 
// Java 21: Record Pattern
if (obj instanceof Point(int x, int y)) {
    System.out.println(x + ", " + y);  // 바로 구조 분해!
}
 
// 중첩 Record도 가능
record Circle(Point center, double radius) {}
record Point(int x, int y) {}
 
if (shape instanceof Circle(Point(int x, int y), double r)) {
    System.out.printf("원 중심: (%d, %d), 반지름: %.1f%n", x, y, r);
}

3. Switch Expressions + Sealed Classes

// Sealed Class로 도메인 타입 안전하게 표현
sealed interface PaymentResult
    permits PaymentResult.Success, PaymentResult.Failure, PaymentResult.Pending {}
 
record Success(String transactionId, long amount) implements PaymentResult {}
record Failure(String errorCode, String message) implements PaymentResult {}
record Pending(String paymentKey) implements PaymentResult {}
 
// Switch Expression으로 모든 케이스 처리 강제
String message = switch (result) {
    case Success(var txId, var amount) ->
        "결제 성공! 거래번호: " + txId + ", 금액: " + amount;
    case Failure(var code, var msg) ->
        "결제 실패 [" + code + "]: " + msg;
    case Pending(var key) ->
        "결제 대기 중: " + key;
    // 컴파일러가 모든 케이스 처리 강제 (누락 시 컴파일 에러)
};

4. SequencedCollection

// Java 21 이전: 첫/마지막 요소 접근이 자료구조마다 다름
list.get(0);                    // List
deque.peekFirst();              // Deque
linkedHashSet.iterator().next() // LinkedHashSet... 😓
 
// Java 21: 통일된 SequencedCollection 인터페이스
list.getFirst();   // ✅
deque.getFirst();  // ✅
linkedHashSet.getFirst(); // ✅
 
// 역순 뷰도 간단하게
list.reversed().forEach(System.out::println);

[ ] synchronized → ReentrantLock 변환 검토
