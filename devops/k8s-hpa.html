DevOpsKubernetes HPA 오토스케일링

Kubernetes HPA로 글로벌 세일 트래픽 대응하기

#kubernetes#hpa#keda#devops#scaling

문제: 나이키 세일은 예측 불가능하다

Nike Korea의 트래픽은 초 단위로 30배까지 급증합니다.

🕐 평시:      50 RPS (초당 요청)
🔥 세일 시작: 1,500 RPS (30배 급증, 순식간에)

수동 스케일링으로는 절대 대응이 안 됩니다.

HPA (Horizontal Pod Autoscaler) 기본

# 기본 CPU 기반 HPA
apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler
metadata:
  name: order-service-hpa
spec:
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: order-service
  minReplicas: 3
  maxReplicas: 50
  metrics:
    - type: Resource
      resource:
        name: cpu
        target:
          type: Utilization
          averageUtilization: 60  # CPU 60% 초과 시 스케일아웃
    - type: Resource
      resource:
        name: memory
        target:
          type: AverageValue
          averageValue: 512Mi

CPU 기반 HPA의 함정: CPU가 급증하고 나서야 스케일아웃이 시작됩니다. 스케일아웃에 60~90초가 걸리는데, 그 사이에 사용자는 이미 에러를 겪습니다. 선제적 스케일링이 필요합니다.

KEDA — 커스텀 메트릭 기반 오토스케일링

**KEDA(Kubernetes Event-Driven Autoscaling)**은 CPU/Memory 외에 외부 메트릭으로 스케일링할 수 있습니다.

다이어그램 로딩 중...
# KEDA - Kafka 큐 깊이 기반 스케일링
apiVersion: keda.sh/v1alpha1
kind: ScaledObject
metadata:
  name: order-service-scaler
spec:
  scaleTargetRef:
    name: order-service
  minReplicaCount: 3
  maxReplicaCount: 100
  triggers:
    - type: kafka
      metadata:
        bootstrapServers: kafka:9092
        consumerGroup: order-processor
        topic: order.created
        lagThreshold: "100"  # 큐에 100개 쌓이면 스케일아웃

예측적 스케일링 (Predictive Scaling)

Nike 코리아만의 패턴을 활용했습니다. 세일 시작 10분 전에 미리 스케일아웃합니다.

# 세일 이벤트 스케줄러 (Python CronJob)
import subprocess
from datetime import datetime, timedelta
 
SALE_EVENTS = [
    {"name": "Nike Day", "start": "2026-03-01T10:00:00"},
    {"name": "Black Friday", "start": "2026-11-28T00:00:00"},
]
 
def pre_scale_for_sale(event):
    """세일 10분 전 미리 스케일아웃"""
    target_replicas = 80
 
    subprocess.run([
        "kubectl", "scale", "deployment", "order-service",
        f"--replicas={target_replicas}"
    ])
    print(f"[{event['name']}] Pre-scaled to {target_replicas} replicas")

평시

order-service: 3 replicas
payment-service: 3 replicas
product-service: 5 replicas
CPU: ~20%

세일 준비 (10분 전)

order-service: 80 replicas  ← 예측적 스케일
payment-service: 50 replicas
product-service: 30 replicas
CPU: ~5% (대기 중)

세일 중

order-service: 80~100 replicas (KEDA 자동)
payment-service: 50~120 replicas
CPU: ~65%
RPS: 1,500

종료 후

KEDA가 자동으로 minReplicas까지 스케일인
약 30분에 걸쳐 점진적 축소
