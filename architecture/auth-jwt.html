왜 세션 대신 JWT인가

세션 기반

클라이언트                서버                   Redis
  |--- 로그인 요청 ------->|                      |
  |                       |--- 세션 저장 -------->|
  |<-- Set-Cookie: sid ----|                      |
  |                       |                      |
  |--- API 요청 (sid) ---->|                      |
  |                       |--- 세션 조회 -------->|
  |                       |<-- 사용자 정보 --------|
  |<-- 응답 --------------|                      |

✅ 즉각적인 로그아웃(세션 삭제)
✅ 서버가 세션 상태 제어 가능
❌ 서버가 stateful → 수평 확장 시 세션 공유 필요 (Redis 필수)

JWT 기반

클라이언트                서버 (stateless!)
  |--- 로그인 요청 ------->|
  |<-- Access Token -------|   (서명된 JWT, 15분)
  |    Refresh Token       |   (Httponly Cookie, 7일)
  |                        |
  |--- API 요청 (AT) ------>|
  |   JWT 서명 검증만!      |   (DB 조회 없음!)
  |<-- 응답 ---------------|

✅ 서버 stateless → 수평 확장 쉬움
✅ DB 조회 없이 토큰 검증 (성능)
❌ 토큰 탈취 시 만료 전까지 막기 어려움

선택 기준

저희의 선택: JWT with Refresh Token Rotation

  • Access Token: 15분 (짧게!)
  • Refresh Token: 7일, HttpOnly Cookie
  • 탈취 감지: Refresh Token 1회용 + 재사용 감지 시 전체 세션 무효화

핵심 구현: Refresh Token Rotation

@Service
@RequiredArgsConstructor
public class RefreshTokenService {
 
    private final RedisTemplate<String, String> redisTemplate;
    private final JwtProvider jwtProvider;
 
    private static final String RT_PREFIX = "rt:";
    private static final String BLACKLIST_PREFIX = "bl:";
 
    @Transactional
    public TokenPair rotate(String oldRefreshToken) {
        String userId = jwtProvider.extractUserId(oldRefreshToken);
        String redisKey = RT_PREFIX + userId;
 
        // 1. Redis에서 저장된 RT 조회
        String storedToken = redisTemplate.opsForValue().get(redisKey);
 
        if (!oldRefreshToken.equals(storedToken)) {
            // ⚠️ RT 재사용 감지 → 토큰 탈취 가능성!
            // 해당 사용자의 모든 세션 무효화
            redisTemplate.delete(redisKey);
            throw new TokenReuseException("토큰 재사용이 감지되었습니다. 재로그인이 필요합니다.");
        }
 
        // 2. 새 토큰 발급
        String newAccessToken = jwtProvider.generateAccessToken(userId);
        String newRefreshToken = jwtProvider.generateRefreshToken(userId);
 
        // 3. Redis RT 교체 (원자적 업데이트)
        redisTemplate.opsForValue().set(
            redisKey,
            newRefreshToken,
            7,
            TimeUnit.DAYS
        );
 
        return new TokenPair(newAccessToken, newRefreshToken);
    }
}

Spring Security 설정

@Configuration
@EnableWebSecurity
@RequiredArgsConstructor
public class SecurityConfig {
 
    private final JwtAuthenticationFilter jwtFilter;
 
    @Bean
    public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
        return http
            // JWT 기반이므로 세션 사용 안 함
            .sessionManagement(s -> s.sessionCreationPolicy(STATELESS))
            // CSRF 비활성화 (JWT + SameSite Cookie로 대응)
            .csrf(AbstractHttpConfigurer::disable)
            // CORS 설정
            .cors(cors -> cors.configurationSource(corsConfigSource()))
            .authorizeHttpRequests(auth -> auth
                .requestMatchers("/auth/**", "/actuator/health").permitAll()
                .requestMatchers("/admin/**").hasRole("ADMIN")
                .anyRequest().authenticated()
            )
            // JWT 필터를 UsernamePasswordAuthFilter 앞에 삽입
            .addFilterBefore(jwtFilter, UsernamePasswordAuthenticationFilter.class)
            .build();
    }
}

보안 체크리스트

실수하기 쉬운 JWT 보안 설정들:

// ❌ 위험: 알고리즘을 'none'으로 설정할 수 있음
Claims claims = Jwts.parser()
    .setSigningKey(secret)
    .parseClaimsJws(token)
    .getBody();
 
// ✅ 안전: 허용 알고리즘 명시
Claims claims = Jwts.parserBuilder()
    .setSigningKey(Keys.hmacShaKeyFor(secret.getBytes()))
    .requireAlgorithm(SignatureAlgorithm.HS256.getValue())  // 반드시 명시!
    .build()
    .parseClaimsJws(token)
    .getBody();
