2025년 회고 — 완료하지 못한 것들에 대하여

#retrospective#2025#year-review#growth

매년 12월 31일, 올해도 어김없이 회고 글을 씁니다. 올해는 조금 다르게, 성공보다 실패와 미완성에 집중해보려 합니다.

2025년 목표 vs 실제

목표계획결과회고
기술 블로그 운영주 1회3개월 운영 후 중단콘텐츠 생산 > 완성도 집착 문제
오픈소스 기여3개 PR1개 머지진입 장벽 예상보다 높음
MSA 전환 완료2분기4분기 완료레거시 의존성 과소평가
Java 인증 취득상반기미완업무 우선순위에 항상 밀림
사이드 프로젝트1개 출시스케치만 존재완벽주의가 시작을 막음

목표 달성률: 40%. 예년보다 낮습니다.

가장 후회되는 것: 블로그 중단

3월까지 꾸준히 쓰던 블로그를 업무 바쁨을 핑계로 중단했습니다.

지금 돌아보면 블로그를 쓰던 3개월이 오히려 업무 이해도가 높아지던 시기였습니다. 글로 정리하는 것 자체가 학습이었는데, 바빠서 배움을 포기한 셈입니다.

2026년에 이 블로그를 다시 시작한 이유입니다.

기술적으로 배운 것

✅ 잘된 것

Kafka를 제대로 이해했습니다. 이론은 알았지만, 프로덕션에서 Consumer Lag이 쌓이고, Partition Rebalancing으로 서비스가 순간 멈추고, DLQ를 실제로 운영해보면서 비로소 이해했습니다.

// 2025년에 가장 많이 고민한 코드: Consumer 중복 처리 방지
@KafkaListener(topics = "order.created")
public void consume(OrderCreatedEvent event) {
    // Idempotency 체크 — 같은 메시지가 두 번 오면?
    if (processedEventRepository.exists(event.getEventId())) {
        log.info("Duplicate event ignored: {}", event.getEventId());
        return;  // 이게 없으면 이중 결제 발생
    }
    
    processOrder(event);
    processedEventRepository.save(event.getEventId());
}

❌ 아직 부족한 것

  • 데이터 엔지니어링: Spark, Flink 등 대용량 데이터 처리 파이프라인을 제대로 모름
  • ML Ops: AI 서비스가 늘어나는데 ML 시스템 설계를 모름
  • 네트워킹 심화: eBPF, Cilium 등 최신 K8s 네트워킹 레이어

2026년 계획

작게 시작하고, 꾸준히 하고, 완성하지 못해도 괜찮다.

  1. 이 블로그를 1년 유지하기 — 월 2~3편, 퀄리티보다 지속성
  2. 오픈소스 기여 2건 — 거대한 PR 1개보다 작은 PR 여러 개
  3. Java 21 + Spring Boot 3.x 마스터
  4. 팀 주니어 개발자 멘토링 — 가르치면 배운다

새해 다짐 대신: 완료하지 못한 것에 죄책감을 갖지 않기로 했습니다. 미완성이어도 시작했다는 것이 중요합니다.
